# Offer design

These are checklists from Alex Hormozi's published work ($100M Offers, $100M Leads).
They are one practitioner's heuristics, not laws. Use them as a structure, and let the
product's own facts fill it.

## 1. Where this skill applies, and where it must not

- Use it for marketing content: advertisements, landing pages, pitches, lead magnets,
  and pricing pages.
- Do not use it for the interface copy inside an application.
- Read the project's decision record first. When it restricts the register - wellness,
  medical, financial, legal - that record wins, and the urgency and scarcity tools in
  section 4 are not available.

## 2. The value equation

Value rises with the dream outcome and with the perceived likelihood of it. Value falls
with the time to the result and with the effort the customer must give. The four levers:

- State the dream outcome in the customer's words, not in the product's features.
- Raise the perceived likelihood with proof: real numbers, named results, a guarantee.
- Cut the stated time to the first result. Name the time.
- Cut the perceived effort. Show what the product does, so the customer does not.

Hormozi gives the most weight to the two dividers: a faster and easier path raises
perceived value more than a larger promise does.

## 2a. Name the substitute first

An offer competes with what the customer uses today, not with nothing. Before you build
the offer, name that substitute - the current tool, the manual workaround, or doing
nothing - and name why the offer beats it. An offer written against a real substitute
is concrete. An offer written as if the customer had no current option describes a
benefit the customer already gets elsewhere.

## 3. Build the offer stack

1. List each problem the customer meets on the path to the outcome.
2. Write one solution for each problem on the list.
3. For each solution, select the delivery form with the highest value to the customer
   at the lowest cost to you.
4. Price against the value of the outcome, not against the cost of the delivery.

An offer built this way answers objections before they are spoken: each named problem
is one objection.

## 4. Sharpen the offer

- **Scarcity**: a limit on quantity. Only a true limit. An invented limit is a lie and,
  in many markets, a legal violation.
- **Urgency**: a limit on time. The same rule: only a true limit.
- **Bonuses**: name each part of the stack separately, each with its own value. One
  named stack outsells one bundled price.
- **Guarantee**: remove the customer's risk. The unconditional form is the strongest.
  A conditional form ties the promise to named terms. A performance form ties the
  seller's payment to the measured results achieved.
- **Name**: build the name from the selectable parts of the naming formula: a magnetic
  reason, the audience, the goal, a time interval, and the container. Use the parts
  that fit. Not every part is required.

Each claim that these tools produce must be true: the number, the limit, the result.
A reviewer must be able to ask for the source of each claim and get one.

## 5. The pitch structures

For an advertisement, the published structure has three parts: call out the audience,
show the value, give one instruction. The hook is the callout, not the whole ad. One
expanded form of the value part, as an adaptation:

1. Name the problem in the customer's words.
2. Show the dream outcome.
3. Give the proof, when real proof exists. Omit this step rather than invent it.
4. State the offer.

One ad gives one instruction at the end. One ad, one action.

For a sales conversation, the CLOSER sequence:

1. **Clarify** why they came.
2. **Label** the problem with them.
3. **Overview** what they already tried.
4. **Sell** the outcome, not the method.
5. **Explain away** each concern.
6. **Reinforce** the decision after it is made.

## 6. Lead magnets

A lead magnet solves one narrow problem completely, free or at a low cost. The solved
narrow problem reveals the larger problem that the paid offer solves. Give the full
solution to the narrow problem. A sample that withholds the answer teaches distrust.

## 7. The limits of this skill

- The frameworks assume a direct-response market. A regulated or trust-first market
  needs the project's own rules first (section 1).
- This skill shapes the message. The facts inside the message follow
  [write-docs](../write-docs/SKILL.md) rules. An empirical claim - a result, a count, a
  speed - must come from a measurement. A business term - a price, a deadline, a
  guarantee amount - must come from the record that approved it.

  as procedures; it does not quote them.
